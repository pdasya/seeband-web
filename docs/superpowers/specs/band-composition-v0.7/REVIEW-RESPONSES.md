**3. **4. Ionized band weights.** **Condition retained.** For parabolic DPB the tested band-2 weight is an empirical convention. Using it in a third band requires a decision in [#247](https://github.com/pdasya/seeband-web/issues/247) and a three-channel check. Kane supports acoustic phonons only. [Conditional-weight revision](https://github.com/pdasya/seeband-web/commit/4dcb81f).

**5. Restoring acoustic plus alloy-disorder scattering.** **Decision documented; production scope remains pending.** Core 0.3.0 replaced the public mixed option with ionized scattering while retaining the kernels. TDD §14 proposes restoring the acoustic/disorder crossover in parabolic transport. The owner selected desktop parity: S-only uses structural inputs alone. Modes with resistivity use the mixed rates, including their effect on S. The three-parabola sum is a Web extension. [Desktop implementation](https://github.com/xAngelswordx/SeeBand/blob/803b0e7a425a0a3f4f59688df77e3ad283ca49a1/modules/fit_module.py#L1392-L1411). The restoration is recorded against P26/#249; forward-reference checks do not validate optimizer, API, or session behavior. [Decision revision](https://github.com/pdasya/seeband-web/commit/8f05da2).

**6. Kane equations and source tables.** **Addressed for the design and fixture.** The review guide records SKB against Lin–Liu, core constants, valley counts, and the parabolic limit. The source equations and table inputs were checked against the paper; see TDD §12 and the [SKB-CORE results](evidence/verify_skb_core.txt). [Source/fixture revision](https://github.com/pdasya/seeband-web/commit/30b63e1).

**7. Mass scale and three-band ambiguity.** **Addressed in the design and synthetic evidence.** TDD §6 explains parabolic common mass-scale invariance and the three-band `bᵢ`/mass near-degeneracy, including dependence on chosen bounds. [MASS-SCALE](evidence/mass_identifiability.txt) checks common-scale invariance and prescribed grid slices showing how edge separation, Hall information and bounds constrain the result; [S-PROFILE](evidence/three_band_s_profile.txt) records the flat S-only profile. The scientific owner selected unit defaults for b₂ and b₃ in three-parabola S-only. Researchers may set either ratio before fitting. Both remain fixed during optimization. The TDD records this decision in §§4, 6 and 15.3. The published prototype and browser transcripts predate the change. [Three-band literature precedent](https://doi.org/10.1016/j.mtphys.2021.100371) · [Acoustic mobility and band parameters](https://www.sciencedirect.com/science/article/pii/S2352847820305062). [Mass scaling and profiles](https://github.com/pdasya/seeband-web/commit/4e4526c).

## Decisions for the scientific and implementation reviewers

- **Three parabolic bands.** The single-mechanism S-only default and manual override are decided (item 7). The physical normalization of the third band’s conductivity still needs independent verification. For ionized impurities, §11 keeps the three-band mode gated on [#247](https://github.com/pdasya/seeband-web/issues/247) and an independent three-channel check.
- **Acoustic plus alloy disorder.** The mode semantics are decided (item 5 and TDD §14). Desktop S-only parity and the three-band extension still need implementation evidence. [#249](https://github.com/pdasya/seeband-web/issues/249) tracks restoration. Preview, optimizer, API and export must eventually use the same forward weights.
- **Kane plus one parabola (Q3).** The relative-weight result for p-PbSe is available for review. Absolute mixed conductivity and the data needed to distinguish α and the single-valley mass are still open. [Evidence required, including candidate measurements](REVIEW.md#evidence-still-needed-for-q3).
- **Recorded decisions.** Q1 uses the desktop carrier balance. Q2 requires integer valley counts. The editable mass is the single-valley DOS mass (item 10). Q4 permits fitting without experimental uncertainties. Q5 gives the researcher responsibility for visually assessing the observed curves. [TDD §9](../2026-11-21-band-composition-design.md#9-implementation-stages-and-questions-for-colleagues).
- **Implementation acceptance.** Review the proposed A2–A4 numerical budgets and select independent benchmarks before release. A6 requires real API calculations, fits, cancellation, export and session restoration. The browser matrix exercises the standalone model editor. [Evidence and acceptance matrix](../2026-11-21-band-composition-design.md#8-evidence-matrix-before-release).
